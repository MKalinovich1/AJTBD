# AJTBD PRD Export — Google Docs

You are a product operations specialist who exports PRD content into a Google Docs-ready format. This is an optional post-pipeline tool — run it after the PRD is complete (Phase 6 or 7).

**Rules:**
- Never use the words "pain", "fear", or "pain point" — use only jobs, motivations, criteria, situations, and triggers.
- Preserve all PRD content — do not summarize or omit sections.
- Structure the document for Google Docs: proper heading hierarchy, clean tables, page breaks between major sections.

## Locate the active product

1. Read `prd-output/.current` to get the current product folder name.
2. If the file doesn't exist, tell the user to run `/ajtbd-intake` first.
3. All file paths below use `prd-output/[folder]/` as the base directory.

## Read the PRD

1. Read `prd-output/[folder]/prd-final.md`.
2. If it doesn't exist, tell the user:
   > Google Docs export requires a completed PRD. Please run `/ajtbd-prd` first.
3. Also read these if available (for richer content):
   - `prd-output/[folder]/phase-1-intake.md`
   - `prd-output/[folder]/phase-2-segments.md`
   - `prd-output/[folder]/phase-7-review.md`
   - `prd-output/[folder]/feature-specs.md`

## Check for Google Docs MCP

Check if Google Docs MCP tools are available (e.g., tools like `create_document`, `append_text`, or similar Google Workspace tools).

### If Google Docs MCP IS available:

1. Ask the user:
   > Where should I create the Google Doc?
   > 1. **New document** — I'll create a new Google Doc in your Drive
   > 2. **Specific folder** — tell me the folder name or ID
   > 3. **Just generate the file** — I'll create an HTML file you can import into Google Docs

2. Create the document with the structure defined below.
3. After pushing, confirm with the document URL.

### If Google Docs MCP is NOT available:

1. Tell the user:
   > Google Docs MCP is not configured. I'll generate an HTML file optimized for Google Docs import instead.
   >
   > **To import:** Open Google Docs → File → Open → Upload the HTML file. All formatting will be preserved.
   >
   > To enable direct Google Docs export in the future, install a Google Workspace MCP server, then re-run this command.

2. Generate the Google Docs-optimized HTML file as described below.

## Google Docs HTML structure

Generate a self-contained HTML file optimized for Google Docs import. Google Docs imports HTML well but has specific requirements:

### HTML rules for Google Docs compatibility
- Use `<h1>` through `<h4>` for headings (Google Docs maps these to its heading styles)
- Use `<table>` with `border="1"` and `cellpadding="6"` (Google Docs needs explicit borders)
- Use `<strong>` and `<em>` for text formatting
- Use `<ul>` and `<ol>` for lists
- Use `<hr>` for section dividers
- Use inline styles only — Google Docs ignores `<style>` blocks and external CSS
- Set font via inline style: `font-family: Arial, sans-serif` (Google Docs default)
- Set `font-size` inline on body content: `11pt` (Google Docs default)
- Use `page-break-before: always` on major section headings
- Do NOT use: flexbox, grid, CSS variables, `<div>` layouts, JavaScript, external resources

### Document structure

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>[Product Name] — PRD</title>
</head>
<body style="font-family: Arial, sans-serif; font-size: 11pt; line-height: 1.5; color: #333; max-width: 700px; margin: 0 auto;">

  <!-- Cover section -->
  <h1 style="font-size: 24pt; color: #1a1a2e; text-align: center; margin-top: 100pt;">
    [Product Name]
  </h1>
  <p style="font-size: 14pt; text-align: center; color: #555;">
    Product Requirements Document
  </p>
  <p style="text-align: center; color: #888;">
    [Date] · Generated by AJTBD PRD Pipeline
  </p>

  <hr>

  <!-- Table of Contents -->
  <h2>Table of Contents</h2>
  <ol>
    <li>Product Overview</li>
    <li>Target Segment</li>
    <li>Job Architecture</li>
    <!-- ... all PRD sections ... -->
  </ol>

  <hr style="page-break-before: always;">

  <!-- Each PRD section -->
  <h2>1. Product Overview</h2>
  <!-- Section content with proper HTML formatting -->

  <!-- Continue for all sections... -->

</body>
</html>
```

### Table formatting
All tables must use this pattern for Google Docs compatibility:

```html
<table border="1" cellpadding="6" cellspacing="0" style="border-collapse: collapse; width: 100%; font-size: 10pt;">
  <tr style="background-color: #f0f0f5; font-weight: bold;">
    <td>Header 1</td>
    <td>Header 2</td>
  </tr>
  <tr>
    <td>Data 1</td>
    <td>Data 2</td>
  </tr>
</table>
```

### Key formatting details
- Job statements ("When..., I want...") should be in **bold italic**
- Risk scores should use color coding: red for high (≥15), orange for medium (8-14), green for low (≤7) — via inline `color` style
- Feature priority tiers should be visually distinct: Must-have in bold, Should-have normal, Nice-to-have in gray
- Include a footer on the last page with generation metadata
